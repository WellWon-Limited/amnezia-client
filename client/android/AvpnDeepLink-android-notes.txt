AVPN (Task 13) — Android: обратный диплинк ПЕРЕНОСА («как SIM») на новое устройство.
✅ ПОДКЛЮЧЕНО (2026-07-03) — реализация ПРОЩЕ первоначального плана: без нового JNI-класса,
переиспользован существующий конвейер доставки строк из ImportConfigActivity.

Реальный маршрут:
1) AndroidManifest.xml (ImportConfigActivity): intent-filter scheme="tribe" (все tribe://-ссылки:
   transfer + рефералка /r/) + App Link https://tribevpn.com/transfer (autoVerify; заработает после
   выкладки /.well-known/assetlinks.json бэком — TRANSFER-KEYS-BACKEND-HANDOFF §3.B1.2). <!-- AVPN -->
2) ImportConfigActivity.kt readConfig(): схемы "tribe" и "https"(host=tribevpn.com) →
   startMainActivity(url) — тот же путь, что vpn://-конфиги (ACTION_IMPORT_CONFIG → AmneziaActivity →
   QtAndroidController.onConfigImported). // AVPN
3) coreSignalHandlers.cpp initAndroidConnectionHandler(): AVPN-guard в лямбде importConfigFromOutside —
   строки tribe://… / …tribevpn.com/… НЕ конфиг → AvpnDeepLink_handleUrl(url) и return (импорт не
   открывается). // AVPN, под #ifdef AVPN_ENGINE_ENABLED.
4) Дальше общий кросс-платформенный путь (как iOS): AvpnDeepLinkBridge извлекает токен →
   transferRequested → AvpnEngineQml::redeemTransfer → POST /v1/transfer/redeem → РОТАЦИЯ
   subscription_token → подписка на ЭТОМ устройстве (старое бэкенд гасит fleet-wide).

Скан QR на Android: кнопка «Сканировать QR» (PageAccountTribe) → ImportController.startDecodingQr() →
нативная CameraActivity → QtAndroidController.decodeQrCode → AVPN-guard в
ImportUiController::decodeQrCode (tribe://… / tribevpn.com/transfer → AvpnDeepLink_handleUrl,
return true = сканер закрывается). // AVPN

assetlinks.json (https://tribevpn.com/.well-known/assetlinks.json) — на бэк-команде (handoff §3.B1.2):
sha256 релизного keystore + package name. До выкладки https-линки открываются через chooser/браузер,
custom scheme tribe:// работает сразу.
